# 图片来源与每日地图

核验日期：2026-10-16。

## 当前项目的图片顺序

1. **高德 POI 地点照片**：用已有高德 Web 服务 Key 查询景点或餐馆，复用同一个已核验 POI 的坐标与照片。优先显示地点照片，失败时尝试该 POI 的其他照片；不需要再申请图片 Key。
2. **Unsplash 搜索**：无地点照片时使用逐站关键词，尝试较短的相关查询。宽泛菜品图明确标注为意象配图，不声称是该餐馆实拍。保留摄影师署名、原图链接和导出使用记录。
3. **南京精选照片**：仅用于匹配的南京景点和菜品，不套用到其他城市。
4. 无可靠结果时显示缺图状态，已有行程可点击「补全图片」。封面从景点图片中选择，不以餐馆图替代目的地风景。

高德照片来自 POI 返回的公开图片地址，保留高德地点来源链接。接口额度以账号控制台为准；接口能返回图片不等于图片获得 CC0 或无限商用授权。项目没有抓取网页私有接口或把图库原图重新分发到仓库。

## 每日地图的实现

- 根据目的地所属地级市/自治州查询，覆盖巍山等周边县域。清理名称中的片区描述，保留明确门店分支，排除同名酒店、停车场和出入口等错误候选。
- 多个候选无法区分，或者「机场/火车站」尚未选定时，保留待核验状态。宽泛区域标记明确说明为代表位置。
- 高德调用共用限速与 QPS 错误重试；已有行程打开地图时补齐坐标，也可点击「重新核验」。
- 标记编号保留当天行程原始序号，中间缺坐标时不重新编号。地图缓存包含地点坐标，补齐后不会继续使用旧图。
- 网页和导出的 HTML 共用高德 JS API 交互地图：拖动平移、滚轮/双指缩放、缩放按钮、一键全览、展开地图，点击编号查看地点、时间、说明与高德链接。
- HTML 每天各有一张交互地图，按日期显示当天已核验地点与顺序连线。全程总览按天配色，显示全部已核验地点；重复坐标合并编号，弹窗保留每次停留。同一天缺少坐标时不改变后续编号。
- 使用独立的 `AMAP_JS_KEY`（Web 端 / JS API），新申请的 Key 还需 `AMAP_JS_SECURITY_CODE`。在「模型与工具 → 外部工具」配置，修改后刷新页面。网页端凭据会进入浏览器和导出的 HTML，建议使用专用 Key 并配置适合使用场景的域名白名单；`AMAP_KEY`（Web 服务）始终留在后端。
- 交互底图由高德在线提供，导出文件直接打开即可使用，不依赖本项目后台运行。断网、SDK 加载失败、未配置 JS Key 时显示内嵌静态地图；打印时也使用静态图。照片使用来源站点链接，需要联网。
- 未核验坐标不在交互地图上标注；没有已核验地点时保留说明和顺序示意。连线表示访问顺序，不代表实际道路导航。
- 静态图最多 10 个标记、4 条折线；静态总览会注明截断，交互地图不受这个静态接口限制。

官方参数依据：[静态地图](https://lbs.amap.com/api/webservice/guide/api/staticmaps)、[POI 搜索与照片字段](https://lbs.amap.com/api/webservice/guide/api-advanced/search)。

交互地图依据：[JS API 加载](https://lbs.amap.com/api/javascript-api/guide/abc/load)、[安全密钥配置](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。新申请的 Key 按官方指南配置安全密钥；若配置域名白名单，分享后的 HTML 使用环境也需符合该 Key 的限制。

## 新行程在生成阶段准备资源

景点、美食和路线专家需传递具体地点名、门店分支与工具返回的 POI id。总规划师通过 `poiId` 引用工具证据；模型提供的坐标和图片 URL 不会直接用于地图或配图。

工作流在发出完成事件前依次执行地点核验、图片匹配、所有每日地图与全程总览生成。已有专家 POI 证据会被复用，缺少匹配时再查询。协作过程会显示各阶段进度，行程中保存 `assets` 检查结果，缺图、缺坐标、地图服务失败会明确记录为部分可用，不伪造资源。

成功生成的地图以不含 API Key 的缓存文件保存到被 Git 忽略的 `.data/maps/`，有效期 30 天；缓存标识包括地点坐标和配置摘要。打开页面和导出 HTML 复用已生成的地图，服务重启后也能读取。只有缺失、失效或坐标发生变化的资源需要重新生成。「补全图片 / 重新核验」用于补救外部服务故障和旧行程，正常新行程不依赖这些按钮。
