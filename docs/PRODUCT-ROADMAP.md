# 下一阶段产品优化计划

[返回 README](../README.md)

## 当前判断

Roam 已具备旅行规划产品的完整主流程：提出需求、比较方案、专家协作、生成图文计划、检查可行性、局部调整和导出随行手册。此次补齐的修改预览、撤销、交通核验与逐项事实状态，让用户能够检查并修正计划，适合继续小范围真实使用验证。

当前定位仍是旅行决策辅助工具。实时可订票价、预约状态、房态、未来交通与现场开放等环节存在缺口；多人账户和长期任务可靠性也尚未达到公开服务要求。下一阶段优先提升行程可执行性和证据质量，暂不增加专家数量。

## 已完成本轮：让已发现的问题更容易解决

### 冲突驱动的局部重排

已提供冲突修复入口，以及保留地点、宽松重排两种策略。规划师读取交通分段、开放信息、锁定项和班次约束，最多两轮生成并重验，返回冲突更少的候选，展示前后对比；无法消除的冲突继续保留。预览、应用、撤销及 HTML 手册同步。

验收：固定测试集中，每个方案都有修改前后冲突数量、时间与费用差额；锁定项零变动；失败不会覆盖原行程。先统计当前基线，再制定冲突消除率目标。

### 出发与返程约束

已支持确认到达/离开车站或机场、班次时间、换乘偏好、老人儿童及行李情况。可引用已有票务查询或手动填写，通过日期、首末站位置和进出站缓冲校验。班次信息与时间轴分别存储，未购票状态明确保留。

验收：列车/航班出发时间与站点游览时间分开存储；校验进站、安检、交通及到达缓冲；缺少班次时保留清晰提示。

### 费用口径统一

已提供费用账本，按人、按房晚、整笔计费，支持上下限、费用依据、口径核对与停留点关联。旧预算保留总额并标注待核对；不能可靠拆分的余额在相关行程变化后标为未知，避免重复计费。混合票种的优惠规则仍需手动列项。

验收：删站、换店、改变人数后，项目与总额可追溯重算；未知费用不按零处理；酒店、跨城票务与市内交通不会重复计费。

## 下一优先：减少信息缺口

### 官方信息与预约清单

为热门场馆补充官网、预约入口、周期性闭馆和临时公告的证据链接。允许用户手动标注已预约、已订房、已购票，并区分用户确认与平台查询。

验收：开放、票价、预约各自关联证据和时间；错误城市、旧公告和仅有搜索摘要的条目不能提升为已确认。

### 出发前复核

先提供手动「出发前检查」：刷新天气、市内路线、票务和营业信息，展示变化及受影响的日期。待账号和通知设置完成后，再增加用户主动订阅的提醒。

验收：只提示有意义的变化；旧结果在刷新失败时保留并标注；不自动修改用户已确认的行程。

### 图片匹配与可用性

维持高德地点照片优先，增加中文地点/门店别名、去重、失效图缓存和图片覆盖率统计。扩展图片提供方前检查接口、署名和授权；搜索引擎图片结果不能直接视为免费素材。

验收：地区不相关的照片不作地点实拍展示；每张图有来源；失效图片可替换且不反复请求。

## 第三优先：为部署和规模做准备

| 工作 | 交付与验收 |
| --- | --- |
| 用户数据隔离 | 账户、独立旅行记录和配置权限；跨账户访问有自动化测试 |
| 数据库与任务队列 | 替代 JSON 单进程存储；断线和重启能恢复可恢复阶段，版本提交保持原子性 |
| 调用成本与可靠性 | 记录每次规划的模型用量、工具耗时、缓存命中、失败原因；支持成本上限与超时 |
| 产品效果评测 | 以真实需求建立路线测试集，统计首稿可用率、地点覆盖率、时间冲突率、用户修改量和导出完成率 |
| 分享与出行模式 | 有权限和有效期的只读分享、当天路线优先、打开导航、可携带静态手册 |

建议按以上顺序分阶段交付。每一阶段先选南京、苏州、大理等不同城市和步行/公共交通/自驾场景做验证，再扩大覆盖范围。
