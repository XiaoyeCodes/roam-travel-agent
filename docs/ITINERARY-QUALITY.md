# 行程修改与信息核验

[返回 README](../README.md)

## 调整已经生成的行程

在「每日行程」选择日期，点击「调整第 N 天」；也可点击时间轴中的「编辑这一站」。

- **告诉智能体**：用自然语言描述减轻强度、雨天备选、换餐馆等要求。只处理选中的一天，可以锁定已有停留点。
- **直接编辑**：修改地点、开始时间、停留时长、费用、说明和提醒，或移除、上移、下移一站。费用按全体旅客该项小计，未知金额留空。
- **预览变化**：查看新增、移除、字段和顺序变化，以及参考预算差额、交通耗时变化、时间冲突。预览不会替换原行程。
- **确认应用**：保存为新版本。其他日期保留，地图、地点照片和时间核验随修改更新。关闭窗口可稍后继续查看；已经完成的预览可在服务重启后继续应用。
- **撤销上次修改**：恢复对应的行程和预算。保留最近 10 次可撤销修改；撤销后版本号继续递增，防止旧窗口覆盖当前内容。

锁定会保护已有地点的名称、时间、时长、费用、说明和相对顺序；应用后记住锁定选择。要手动修改锁定项，先取消勾选。模型输出如果破坏锁定约束，会要求修正；失败时保留原计划。运行中的预览可取消，被服务重启中断时需重新生成。

地点调整目前限于日内，不支持跨日期搬移。「班次与衔接」「费用与人数」属于全程设置，分别通过预览确认后应用；全程费用编辑可能因人数改变而重算锁定地点的费用，地点和时段仍保留。住宿推荐和交通叙述作为原规划背景保留，以新保存的班次约束和费用明细为准。

## 从冲突发起修复

点击每日核验区的「生成冲突修复建议」。可选保留全部地点、仅调整时间与停留时长，或允许减少/替换未锁定地点的宽松策略。规划师读取当前交通分段、开放信息、锁定项和已确认班次。

候选方案完成后重新核验。如果仍有时间冲突，最多再反馈一轮具体缺口给模型；仅当第二轮冲突更少时采用它。预览展示修正轮次、前后冲突数、待确认事项数、已知停留与交通时间，以及费用差额。锁定项或班次导致无解时保留冲突说明，用户可以放弃候选或调整要求；不会把未知信息自动标成已解决。

## 班次与行程衔接

在行程页点「班次与衔接」，或从预算页进入。分别确认目的地到达和返程出发的日期、具体车站/机场、班次时间及班次号；可引用已有铁路/机票查询，也可手动填写。时间统一为北京时间。查询来源由服务端核验，改动时刻后改为用户填写；两种来源均不代表已购票。

到达关联当天首站，返程关联末站，均为交通停留点。没有合适站点时可在预览中新增，随后执行坐标、地图与时间核验。模型重排不能移除这些锚点或改换站名；解除班次关联不会删除时间轴中的旧站点。

基础缓冲可以调整，另可增加儿童、长者、大件行李及额外预留。铁路初始出站/进站预留为 20/45 分钟，飞机为 45/120 分钟；儿童、长者分别加 15 分钟，大件行李加 10 分钟。这些是规划参数，不代表官方登乘规定。确认班次后，站间交通的 10 分钟缓冲与进出站缓冲分别计算，避免重复添加默认站点缓冲。

少换乘偏好在每日交通方式选择「公交/地铁」时生效，使用[高德公交路径规划](https://lbs.amap.com/api/webservice/guide/api/direction)的最少换乘策略。请求包含预计离开上一站的时间，路线缓存区分日期、时间和策略。跨午夜的进出站缓冲暂不自动拆成跨日安排，会提示调整。

## 逐笔费用与人数

「费用与人数」统一维护每笔开销，支持每人、每间每晚和整笔三种计费单位。人数、间数、晚数是独立输入；修改人数不会擅自改变房间数。单价可填写上下限，未知时上下限同时留空。每笔有依据/票种说明、填写来源和口径核对状态。

- 景点门票和餐饮可各自关联时间轴停留点，每站至多一笔；酒店和往返交通独立计费，避免再次加入停留点展示金额。
- 删除已关联停留点会移除对应费用，修改金额会同步账本。新增/替换项目若与原分类未分配金额无法可靠区分，会将该余额标为未知，保留新项目，避免重复相加。
- 旧行程保留原预算总额；仅在金额能够对应时按人数均摊或按房晚拆分，均标注待核对。这些均摊单价不代表真实成人/儿童票种价格。
- 页面和手册展示已知费用区间，余量按已知上限计算。未知费用不计入区间；修改人数后无法重算的独立停留点金额清空，整笔项目提醒重新核对。

目前每人项目使用统一单价；混合成人/儿童票种可拆成不同的整笔项目并写明计算依据，尚未自动适用优惠规则或同步实时报价。

## 每日时间与交通

新行程生成和修改预览阶段均自动执行核验。在网页中也可选择步行、驾车/打车、公交/地铁或步行加打车，再点击「核验当天」。

- 使用已匹配的高德 POI 坐标查询相邻停留点的路线、距离和参考耗时。自动模式按直线距离 1.5 km 选择步行或驾车；此阈值不代表最优路线。
- 检查开始时间、停留时长、安排重叠、交通预留不足、过长的日程和较长的步行距离。
- 默认站间缓冲 10 分钟；未确认班次的火车站/机场使用 45/90 分钟参考缓冲，确认后改用班次配置并单独检查进出站衔接。
- 查询高德 POI 营业信息；可识别普通时段、周休、跨夜、日期/月段与最晚入场。复杂节假日或临时公告会提示人工确认，缺失信息不会当作全天开放。
- 查询失败、没有坐标、没有 Key 时显示「待核验」，不会生成虚假的路程或把未知交通显示成零分钟。部分查询成功时只统计已取得数据。

结果是行程可行性检查，不代表预约成功或未来路况保证。站间步行不包含景区内部；道路导航入口与游览顺序连线分别展示。

## 逐项可信状态

每个停留点默认显示一行「信息与来源」，展开后查看地点、费用、开放时间、预约和配图各自的依据、来源及查询时间。天气、去返程和住宿也有各自的状态。

每日检查优先展示实际时间冲突与需要补充的操作；同源的地点、路线缺失合为一项地图与交通说明，开放时间缺失按类折叠。没有班次时，同一机场或车站的时间提醒合并为「补充班次」，可直接进入填写入口。原始记录仍可逐层展开，未知信息和冲突状态不因精简展示而改变，旧行程与 HTML 导出使用相同规则。

当前地点与路线自动核验使用国内高德服务和坐标范围。目的地无法解析为有效行政区时停止逐站检索，统一说明服务覆盖缺口，不把所有地点都解释为名称有误或多个匹配；需要覆盖当地的地图来源才能实际补齐海外数据。地点检索已经返回的营业信息直接复用，避免丢弃已有证据。

| 状态       | 含义                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 工具已查到 | 查询返回了该字段的证据；例如地点坐标，不代表票价、营业或预约同时确认 |
| 参考估算   | 计划估价、酒店参考价或相关图库配图                                   |
| 用户提供   | 手动填写的费用，仍不视为实时报价                                     |
| 待确认     | 缺失、错误或无法关联到当前地点/日期的证据                            |
| 需要更新   | 超过项目设置的建议刷新时间                                           |
| 演示数据   | 固定示例，未实时查询                                                 |

当前建议有效期为：地点 30 天、营业信息 7 天、市内路线 24 小时、天气 6 小时、票务 15 分钟。这些是产品刷新策略，不是供应商承诺。未接入预约凭证，所有预约状态仍需用户确认。未取得真实票价的费用始终标为估算或未知。

## HTML 手册

导出采用点击时已经应用的版本快照，包含修改摘要、修复前后冲突数量、每日交通分段、班次与缓冲、费用公式与区间、可信状态及来源。保持每日交互地图、编号和全程总览；网络不可用时使用内嵌静态预览。

HTML 可独立阅读和展开详情。继续修改需要回到网页应用，再导出新版本；文件不会连接本机模型接口或携带服务端密钥。手册记录导出时的核验状态，出发前请在网页更新易变信息。

## 实现与验证

`quality.ts` 在生成阶段核验事实和时间，`revisions.ts` 保存草稿、校验锁定约束并管理版本。浏览器与 HTML 共用状态类型和样式，HTML 单独做文本与链接转义。修改、核验、补图之间使用每任务锁，导出读取快照。

```bash
npm run check
npm test
npm run build
npm run test:revisions
```

最后一项会启动独立 API、隔离旅行数据、使用固定模型响应操作真实浏览器，覆盖预览/应用/撤销、锁定、重启恢复、费用区间、班次关联、冲突修复、HTML 下载、事实展开和手机布局。不会使用用户的旅行记录或真实模型额度。
